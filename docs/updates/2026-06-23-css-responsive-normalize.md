## 1. 背景：发现三套并存且不一致的断点

`responsive.css` 的手机层此前已被你手动从 `768–991` 改成 `max-width:991px`（"平板与手机同尺寸"，

## 2. 统一的断点规范（已写进各文件顶部中文凡例）

```
手机        ≤ 767px          （Site.css 栅格 xs）
平板        768 – 991px       （Site.css 栅格 sm）
手机+平板   ≤ 991px           ← responsive.css "手机层"统一口径（平板与手机同尺寸）
桌面        ≥ 992px
根字号 ladder（仅缩放 html font-size）：≤991:26px · 992–1279:12px · 1280–1919:16px · 1920–2559:18px · ≥2560:20px
```

## 3. 本次实际改动（全部"展示不变"）

- **媒体查询书写统一**：所有 `@media screen and (...)` → `@media only screen and (...)`。
  `only` 对任何现代浏览器与 `screen` 完全等价（只屏蔽十多年前不支持媒体查询的老浏览器），渲染不变。
- **根字号 ladder 下限对齐 992**：`responsive.css` 里 `@media (max-width:1279px){html{font-size:12px}}`
  改为 `@media (min-width:992px) and (max-width:1279px)`。≤991 本就由后面的 `26px !important` 覆盖，
  所以 992–1279 仍是 12px、≤991 仍是 26px，渲染逐像素不变，只是断点更干净。
- **中文凡例 + 分区注释**：三份文件顶部都加了"断点规范"说明；`responsive.css` 内补了大量分区/分节注释。
- **清理死代码**：删掉 `responsive.css` 里已废弃的"核心成员(旧)"大段注释、半截的 `/* 原: 768-991 */`
  迁移注释、以及 20 多行空白间隙；删掉 `Artist.css` 里 4 个**空的占位媒体块**（无任何规则，纯删注释）。
- **同步两处**：`web24.05/Content/...`（运行时配信 + Gitee 部署仓）与 `szaipa2022/Content/...`（git 正本）
  保持一致。

## 4. 为什么没有"强行把断点并到 992"

`responsive.css` 桌面层用的是 `min-width:768px`，与手机层 `max-width:991px` 在 768–991 重叠。
直接改成 `min-width:992px` 看似更干净，但会在 **768px（iPad 竖屏，真实设备宽）** 产生可见变化：
该区间有几个桌面变量是被实际消费的，翻断点后会丢值/变值——

- `--emailLine`（仅 `min-768` 定义，全站页脚邮件订阅框宽 `width:var(--emailLine)`，10+ 处消费）→ 768–991 会丢宽度
- `--zhuangtai`（NewIndex 展讯状态字号）→ 768–991 会从 `.9rem` 变 `1rem`
- `.imgCon_Pub`（15 个出版页用的图片位移）→ 768–991 会失去 `translateY(-20%)`

因本次硬约束是"展示不变"，故 768–991 维持现状，并在文件顶部以"历史兼容区"注释明确标注。
