# 生产 IIS `/Content` 近 90 天访问审计

## 目的与边界

在不停止 IIS、不写数据库、不改动站点文件的前提下，用生产站点 `W3SVC1` 的 W3C 日志复核此前 95.9MB `review-candidate`。本次只读窗口为 **2026-04-14 至 2026-07-13**。

- 日志文件：92 个
- 已解析请求行：553,963
- 跳过日志：0（当天日志用 `FileShare.ReadWrite` 共享读取）
- 唯一 `/Content` 路径：2,881
- 数据库路径基线：沿用 2026-07-12 只读审计的 19 条明确路径
- 服务器文件删除/移动：**0**

可复跑脚本：`scripts/audit-iis-content.ps1`。脚本输出候选根的请求数、成功数、唯一 URL、物理文件数/体积，以及与日志精确匹配的物理文件数；同时把唯一访问路径写到临时清单，便于后续复核。

仓库版脚本随后已在同一 Windows/IIS 环境用 1 天窗口实机复跑：3 个日志、10,954 条请求行、0 跳过、0 畸形路径，`Award`/`layui` 的文件数与字节数和 90 天盘点一致。

`Award` 和 `layui` 的文件最近修改时间均为 **2024-05-08 UTC**。`Award` 主要是一个旧活动微站（含 MP4、独立 CSS/JS/字体和图片），`layui` 是旧版 Layui 静态副本。两者在以下三层均未发现引用：

1. 当前源码静态精确引用；
2. 生产数据库资源字符串只读导出；
3. 生产 IIS 近 90 天 GET/HEAD 日志。

## 为什么其余候选不能清

- `_preview` 虽然大量物理文件在窗口内没有精确命中，但目录本身仍承担线上图片预览流量；缓存文件是否可逐项淘汰取决于生成器与缓存失效策略，不能按“90 天未命中”直接删除。
- `TempFile` 的唯一成功 URL 在当前物理目录中已经找不到，符合临时文件生命周期特征；这反而说明目录可能仍由运行时写入/清理，不能按静态资源处理。
- `js` 的成功请求量最高，旧站仍明确依赖其中多项脚本。
- `Filme` 中的协会章程 PDF 有 206 次成功请求。

## 需要人工确认的下一步

建议只对 `Award` 和 `layui` 做可逆隔离，不直接删除：

1. 先在站点根之外建立带日期的 `legacy-quarantine`；
2. 将两个目录移出 `Content`，记录文件数、字节数与哈希清单；
3. 冒烟首页、新闻、会员、展览、旧后台登录，并观察新产生的 404 日志；
4. 保留隔离副本一段观察期，再决定永久删除。

这一步会改变生产站点文件布局，因此必须取得用户明确确认后才能执行。
