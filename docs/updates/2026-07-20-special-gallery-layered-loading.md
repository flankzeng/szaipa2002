# 特殊展览现场图库分层加载（2026-07-20）

## 范围

三个保留的大型自定义展览页的「现场照片」从重复静态标记改为同一数组驱动
主图与缩略条：

- chunyu3：46 + 46；
- tonggou2：48 + 48；
- tonggou2024：107 + 107。

主图 `src` 先走只读 `ILegacyImagePreviewResolver`，并把精确原路径保留在
`data-original-src`；缩略条永久使用预览/安全回退。作品详情、原图新窗口链接、
开篇/LCP 图均不变。

`publication-special.js` 在 `.mySwiper3` 进入 50% 预加载边界后才：

1. 识别 active / prev / next（类名 + loop 索引双重回退）；
2. 以 `Image` 预载对应原图；
3. 只在成功后替换该三张的 `src`；
4. 用 URL → Promise Map 防止 loop/重复节点重复请求。

无 IntersectionObserver 时保持功能性回退；无 Swiper 时不报错；初始化有幂等保护。
catalog 和现场图库的 navigation/pagination 也改为容器内查找，避免两组 Swiper 串线。

## 实页验证

- 390×844 首屏打开三页，主图/缩略数量分别为 46/46、48/48、107/107；
- 画廊远离视口时 chunyu3/tonggou2 原图恢复数为 0；tonggou2024 仅有 31 张解析器原图回退；
- 接近画廊后 chunyu3/tonggou2 各只恢复 3 张，缩略条分别仍为 46/48 张预览；
- 切换 chunyu3 下一张后，原图集合从 3 增到 4，其余 42 张仍为预览；
- 浏览器实际资源观测：chunyu3 未接近图库时现场图请求为 0；接近后观测到
  40 个预览资源 + 3 个原图资源，而不是 46 张原图；
- 三页均 `scrollWidth == clientWidth == 390`，Swiper 实例数 3/3/2，控制台 0 error。

静态复核还确认原主图路径顺序逐项不变，作品/catalog 之前的图片路径不变，
三页全部 `href` 不变。

三页已统一加载 `publication-special.js`；旧 `publication-tonggou2024.js` 中的共享逻辑已合并，
而没有对应 `.bannerCon` DOM 的死滚动逻辑不再保留。服务器、Content 和数据库均未修改。
