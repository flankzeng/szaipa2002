# 历史访问记录核实与分析（2026-10-29）

## 确实有历史埋点，但三类数据不能混算

用户记得的历史记录不只有日志文件。旧站还把访问写入数据库 `AccessData`、`Diary` 和内容的累计访问字段。这些数据与 IIS 逐请求日志、后来新增的浏览器点击事件各有不同含义。

| 来源 | 当前证据 | 能回答的问题 | 不能据此得出的结论 |
|---|---|---|---|
| `AccessData` / `Diary` | 本地生产镜像里有大量历史记录；不是实时生产查询 | 旧站会话首次访问的日/月趋势 | 真人数、逐页点击或完整访问路径 |
| 旧内容 `ReadCount` / `VisitCount` | 内容详情请求累加，规则还存在历史差异 | 内容累计请求热度的粗略比较 | 特定31天内点击量、去重人数 |
| 正式站 IIS W3C | 已确认正式站 Site ID=1，日志目录 W3SVC1 | 具体路径请求、日期、状态、UA等特征 | 已确认真人、精确点击事件 |
| `requests-*.log` / 浏览器事件 | 源码具备采集能力，是否启用需核部署配置及现存文件 | 有记录时可分析请求/浏览器交互 | 不能从源码存在推断曾经落盘，也不能补录历史点击 |

复核查询（SQLite只读连接，未查询IP）：

```sql
SELECT strftime('%Y-%m', Date), count(*), count(DISTINCT date(Date))
FROM AccessData GROUP BY 1 ORDER BY 1;
SELECT strftime('%Y-%m', Date), sum(VistiTotal), count(DISTINCT date(Date))
FROM Diary GROUP BY 1 ORDER BY 1;
SELECT Id, Title, ReadCount FROM News ORDER BY ReadCount DESC, Id LIMIT 5;
```

`HomeController.HaveViti` 在 Session 中没有 `Home` 标记时，设置标记、增加当天 `Diary.VistiTotal` 并写入一行 `AccessData`。记录包括时间和地理信息，**不含页面路径、UA或来源页**。清除 Cookie、不保留会话的爬虫、不同会话都会影响计数，不能准确识别真人。

旧内容计数在新闻、作品、部分艺术家详情请求中累加，未排除爬虫与重复请求；不同路由规则也不完全一致。旧测试接口可以写入 AccessData，且并非所有测试记录都有明确“测试”标记。现代公开读仓储没有继续递增这些旧字段，后台读取的旧累计数不能当作新站实时流量。

依据：旧站 `Controllers/HomeController.cs` 的 HaveViti/today、详情路由及 TestIpAddList；`Models/AccessData.cs`、`Models/Diary.cs`；现代 `Services/Admin/DashboardAnalyticsRepository.cs`。本次只读代码和聚合数据，没有读取或发布逐条 IP、Cookie、UA、搜索词。

本轮只读现场核实：正式站是 `szaipa` / IIS Site ID 1，当前发布目录 `C:\SzaipaData\releases\af25b3f`（此前“尚未发布”的检查点已过时）。W3C目录 `C:\inetpub\logs\LogFiles\W3SVC1` 的9月28日至10月28日31个文件仍在，合计 **67,634,465 bytes（约64.5 MiB）**。字段含时间、请求路径、方法、状态码、耗时，以及IP、UA和Referer；本轮仅在服务器聚合，不下载这些原始个人记录。

现行发布目录的生产配置字段为 `ServerSecurityRoot=C:\Security`、`RequestAuditEnabled=false`、`AuditDirectory` 为空（生产路径解析由安全根派生到 `C:\Security\audit`）；该目录存在但未发现请求/登录日志。**代码已发布不等于采集已启用**。本轮没有修改开关；部署环境另有配置覆盖时应以最终运行值核对，不能只看模板。现有证据支持“当前配置未启用、当前没有发现这类文件”，不支持“历史从未产生过”的绝对判断。

`2026-10-28-iis-traffic-30days.md` 已由另一轮工作生成。本次不把那份报告当作未经审查的事实：

- “2,023 个 IP 加载 CSS/JS、9,756 次页面请求”只是一组满足资源请求特征的候选数据，**不证明是真人**。自动化浏览器也会请求资源，浏览器缓存又会漏掉真人资源请求。
- IP 数不是人数；不能把“日均约85个候选IP”写成“85人”。共享网络、动态地址和代理均影响去重。
- Referer 缺失不能推断直接访问；App、隐私策略、跨站跳转等均可能不携带来源。
- 没有 CSS/JS 请求不能证明是伪装爬虫；设备 UA 只能说明声明的设备类型。
- 9月28日至10月28日含首尾是31个日历日；不同时间截点、测试流量排除和页面过滤规则的数字不可直接混算。
