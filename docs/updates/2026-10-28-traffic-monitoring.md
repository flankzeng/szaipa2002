# 网站访问与点击监控增强

## 目标与执行约束

- 用户确认只增强现代 .NET 10 网站；旧版 `szaipa2022/` 及原有未提交改动不动。
- 主 Agent 负责协调、审查、整合与验证；三个 `gpt-6-luna` 子 Agent 分别负责请求分类、浏览器事件采集、后台界面。
- 每个主要工作块检查账户 300 分钟额度。约剩余 10% 开始收尾，剩余 5% 不再开发或测试。额度是账户共享且查询并非实时硬限额，提前收尾用于预留保存与调度空间。
- 若额度不足而任务未完，停止子 Agent，更新本文件与 HANDOFF，用应用 heartbeat 自动化按最新 `resetsAt` 重置后两分钟唤醒当前聊天；唤醒后先核额度并读检查点。不得固定假设从停工时间再加五小时，不得重跑已完成工作。
- 本任务不部署生产，不修改生产数据库。

## 实现

1. 请求分析：`TrafficInsights` 分类为机器人、疑似机器人、未判定；保留判定理由，支持页面维度、筛选与分页。
2. 浏览器证据：同源受限采集 view/click；只保留路径，不收集输入或页面文本，不把 JavaScript 事件作为真人证明。
3. 后台：在现有安全监控页面展示请求分析和浏览器事件，说明数据不完整、无数据、读取失败。

入口：`/Staff/SecurityMonitoring`，需要后台登录。新增 `TrafficInsights` 与 `Interactions` 两个只读 JSON 端点。两者按 UTC 日历最近 1–30 天查询；显示时间由浏览器本地化。

- 分类依据：UA 自报自动化标记（非已验证搜索引擎身份）、缺失 UA、常见探测路径、同 IP+UA 每分钟至少 60 次请求、每小时至少 20 个不同 404 路径。没有命中是“未判定”，绝不计作已确认真人。
- 网站分析排除后台和采集端点，避免监控页自身污染。热门页只统计 GET，展示路径与分类数量，明细支持筛选和分页。
- 浏览器采集覆盖公共布局、艺术家布局、新闻详情和三个独立展览页。记录同源链接来源页/目标页，包括新窗口链接；不记录外链、下载、输入值、页面文字或 URL 查询参数。脚本忽略合成 click，但自动化浏览器仍能产生可信浏览器事件，因此这里是交互证据而非身份验证。
- POST 正文最多 2 KiB（包括无 Content-Length 的流式请求），同源校验兼容 HTTP/HTTPS 默认端口；路径规范化后排除后台/API，拒绝编码穿越。按事件 ID 最近 24 小时去重（重启装载最近两日日志），每来源地址每分钟 30 条，最多记忆 2000 个速率键，键池满时拒绝新键。
- 事件日志 `traffic-YYYYMMDD.jsonl` 放在既有 `AuditDirectory`，单日上限 5 MiB/50,000 条，沿用保留天数；汇总有有界读取和不完整提示。请求审计遇读取上限、过大文件或读取失败，新增覆盖信息，不再默认为全量。
- 修复旧 IP 解析直接信任客户端 X-Forwarded-For 的问题，改用连接地址（IIS 或已配置的可信转发中间件可预先规范化它）。部署在额外代理后需核实该地址是访客还是代理，不能盲目信任任意转发头。

## 启用与边界

- 无数据库改表，无 SQL 脚本；设置 `SecurityMonitoring:RequestAuditEnabled=true` 并确保 `AuditDirectory` 是发布目录外、应用池可写的持久目录。关闭时不挂载脚本且采集端点返回 404。
- 仅新上报事件有点击明细，历史请求日志不能反推出点击。JS 被拦截、禁用、网络失败、限流及容量拒绝都会漏报；数值表示已接受的观测，不是绝对人数或完整真实点击总量。
- 当前去重/限流/写入串行控制以单个应用进程为单位。多 worker、IIS 重叠回收或多实例共享目录时可能重复或竞争配额；这类部署应换共享原子存储，不能据此承诺跨实例精确统计。
- 本次仅本地实现和验收，没有发布正式站。正式启用需按项目发布流程部署，并核实目录权限及反向代理来源地址。
