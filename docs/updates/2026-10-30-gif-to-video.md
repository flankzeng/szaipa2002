# 2026-10-30 大 GIF 动图改为静音循环视频

## 背景
新闻正文里共 69 张不同的 GIF，合计 48.8 MB，网站以前不压缩 GIF。

- 23 张 ≥ 300 KB 的大 GIF 占了 46.6 MB，集中在几篇文章：
  - 田晓磊推介：15 张，27.3 MB；
  - 龙游水脉艺术节：3 张，10.3 MB；
  - 富诺得拍卖等。
- 其余都是公众号排版用的小装饰图（分割线、小图标），每张只有几 KB 到几十 KB。

用户确认：“太大了，压缩下”。

## 做法
1. **本机转换**（`scripts/gif-to-video.sh`）：
   - 每张大 GIF 生成同名旁挂文件 `xxx.gif.mp4`：H.264、CRF 28、无音轨、faststart。
   - 同时生成首帧图 `xxx.gif.jpg`，作为视频的 `poster`。
   - 带透明的 GIF 自动跳过，因为 MP4 没有透明，会变成黑底。本次 23 张都不透明。
   - 逐张核对，帧数和时长与原 GIF 一致。放大 2 倍对比画质，与原 GIF 看不出差别；GIF 的抖动噪点反而更少。
2. **网站输出**（`ImageVariants.AddSrcSetToHtml` → `GifVideoTag`）：
   - 正文里的 GIF，如果旁边有 `.gif.mp4`，就输出为 `<video class="gif-video" autoplay muted loop playsinline poster=…>`。
   - 原 img 的 `style` 照搬，`alt` 转为 `aria-label`。
   - 没有旁挂文件的 GIF（小装饰图、以后新同步的 GIF）照旧输出 img。
   - 现场编辑状态下正文不经过这一步，编辑的仍是原 HTML，数据库内容不变。
3. **样式**：`newsread.css` 中 `video.gif-video` 与正文图片使用同一套尺寸和间距，电脑端 45% 宽居中，手机端不超过屏宽。
4. **缓存**：`.mp4` 与图片一样，浏览器缓存 30 天，地址里带版本号。
5. **原 GIF 不改也不删**。删掉旁挂文件，网站就自动回到原 GIF。

## 效果
| | 原 GIF | 视频 + 首帧图 |
|---|---|---|
| 全部 23 张 | 46.6 MB | 8.1 MB + 0.96 MB（约 −81%） |
| 田晓磊推介 | 27.3 MB | 4.6 MB |
| 龙游水脉艺术节 | 10.3 MB | 1.3 MB |
| 富诺得首届拍卖会 | — | 1.6 MB |

## 验证
- 新增测试：
  - 有旁挂文件的 GIF 输出 video，带 poster，`style` 和 `alt` 正确保留；
  - 没有旁挂文件的照旧输出 img；
  - 路径穿越和外链 GIF 不处理；
  - `.mp4` 缓存 30 天。
- 全量测试通过。
- 本地在副本 Content 上打开田晓磊推介，手机宽度 390 下：
  - 13 段视频全部自动播放；
  - 宽 350 px，没有横向溢出。

## 上线步骤
1. 把 46 个新文件（23 个 `.gif.mp4` + 23 个 `.gif.jpg`）按相同相对路径放到服务器 Content 目录。
   - 只新增文件，已存在的文件跳过，不覆盖任何文件。
   - 旧版本代码不认这些文件，所以先放文件不会影响线上。
2. 发布含本改动的版本：先测试站，用户确认后再上正式站。

以后公众号同步进来新的大 GIF 时，服务器上不会自动转换，需要在本机对 Content 副本运行一次 `scripts/gif-to-video.sh`，再把新生成的文件放回服务器。
