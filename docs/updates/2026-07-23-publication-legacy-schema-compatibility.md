# 展览详情旧库架构兼容（2026-07-23）

## 问题

展览公开页新增“重要模板”和“参展作品目录”后，读模型直接投影了新增列
`Publication.Type`、`Publication.Preface`、`Publication.Signature`，并无条件读取
`ExhibitionWork`。当前本地只读旧库尚未应用这些架构变更，任一新字段缺失都会让
`/Home/Publication/{id}` 在查询阶段返回 500。

## 兼容策略

- 先只读取旧 `Publication` 架构已有的字段，确保原普通画廊始终可用。
- 有模板列时才启用重要模板；列不存在时只在该增量查询处降级为 `Type=0`。
- 仅 `Type=1` 时查询作品目录；目录表不存在时视为空列表。
- 除“列/表不存在”外的数据库异常仍会抛出，避免掩盖连接、权限或数据问题。

这不会写入数据库，也不替代后续的正式 schema/data migration。

## 当前数据状态与人工确认点

首页仍保留的固定编号 `92001–92015` 在当前只读库没有对应的 `Publication` 行；兼容后这些
链接会正常得到 404，而不再是 500。要恢复它们的动态详情，必须先人工核对 14 份旧页面内容与
图片命名，再在**本地可写副本**写入 Publication 数据，并在 UI 验收后才考虑发布。此轮未执行任何
数据库写入、服务器或旧发布版改动。

## 验证

- SQLite 回归覆盖缺少 `Type` 列和缺少 `ExhibitionWork` 表两种旧库情形。
- Data：98/98；Web：127/127；总计 225/225。
- Web 构建：0 warning / 0 error。
